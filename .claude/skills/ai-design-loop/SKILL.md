# AI Design Loop — профессиональный дизайн от ИИ только через замкнутый контур

## 0. Первая истина (first principles, не опционально)

1. **LLM слепа.** Это предсказатель токенов: нет сетчатки, глазомера и рендера DOM. Запрос «сделай красиво» без контура проверки = интерполяция по среднему датасета = усреднённое нейрохрючево. Скилл — это **негативный линтер**, не «дизайнер в чипе»; дизайнером модель делает только замкнутый Visual Loop (§6).
2. **Проф-UI — это математика, не вкус.** Конечный автомат состояний (`hover`, `focus-visible`, `active`, `disabled`, `loading`, `error`, `empty`) + сетка 320px→4K + переполнение текста + a11y (WCAG 2.1 AA, контраст ≥ 4.5:1) + Core Web Vitals (CLS = 0).
3. **Байесовский пол.** «ИИ по одному промпту сделает лендинг уровня Awwwards» — базовая ставка ≈ 0.1%. База холодной конверсии неизвестного оффера — **0.8–1.8%** (Unbench/Wordstream класс). Копирование UX-приёмов гигантов (Calendly/Shopify/MasterClass) для «продажи ручки» — **category error**: их конверсию делает тёплый трафик и бренд, а не шапка сайта.
4. **Vision-модель — не штангенциркуль.** Скриншот она читает как гештальт (Spatial Hallucination: не отличит `padding: 14px` от `18px`). Контраст, оверфлоу и доступность отдавай детерминированным линтерам; зрению — только иерархию, ритм и считываемость оффера.

## 1. Негативный фильтр: никогда не генерировать (AI-slop маркеры)

- Дефолтный Inter + сине-фиолетовый градиент + `rounded-2xl` везде.
- Карточки «иконка в кружочке + заголовок + два предложения», три одинаковых в ряд.
- Эмодзи в заголовках и кнопках; стоковые улыбающиеся люди из Unsplash.
- Гигантские пустые паддинги (`py-32`): на 1440p — полтора предложения (для B2B — смерть, см. §5).
- Всё-серое `#64748b` без контрастных якорей (Lack of Contrast Framing).
- **Fake FOMO:** таймер, сбрасываемый `localStorage.clear()`/перезагрузкой; «ведущие эксперты рекомендуют» без фамилии/должности/ссылки (Anonymous Authority); «решим вашу проблему за 1 клик» (Asymmetric Free Lunch); логотипы клиентов без реальных контрактов (проверяется OSINT за минуту).
- Тяжёлые Three.js/WebGL-шейдеры «для вау» на лендингах сложных продуктов: mobile Safari, 15 FPS, утечки контекста канваса, LCP/INP в мусоре. Анимации — усилитель доказательства (§7), не содержание оффера.

## 2. Детерминированные ограничения вместо вкуса

- **Не придумывать стили из головы.** Только дизайн-токены (typography scale, 8pt-сетка отступов, радиусы, палитра) зафиксированные в `design-tokens.json`/конфиге; сверка токенов — на этапе Critic (§6).
- **Компоненты — из систем, где состояния зашиты математически:** Tailwind + shadcn/ui (Radix Primitives) или Catalyst. `aria-*`, фокусы и пропорции приходят из библиотеки, а не из фантазии модели.
- **Few-shot = сырой код проверенных компонентов**, не скриншоты: 21st.dev, Magic UI, Aceternity UI (осторожно: оверхед framer-motion), shadcn/ui. Промпт-витрины (scrolltide/motionin) — источник идей [UNRELIABLE: LEVEL 3], не кода.
- Инструменты-референсы для глаз человека: godly.website (арт-дирекшн), land-book.com (структура лендингов), cta.gallery (кнопки/CTA), footer.design (футеры). Единственный из «12 сайтов для ИИ» с настоящей интеграцией — **60fps.design через MCP-сервер `mcp.60fps.design/mcp`**; landdding/modulify/theinternetdesigns/inspora — вторичные агрегаторы (воронка Azwedo), backgrounds.supply — платные градиенты, мусор.

## 3. Intake перед генерацией (без ТЗ — ХЗ)

Ответы фиксируются ДО первой строки кода:

1. Продукт/оффер в одном предложении; что считается конверсией (действие)?
2. Температура трафика: холодный/тёплый? (определяет §4: symptom-заголовок vs продукт-заголовок).
3. Аудитория и её сегмент (B2B-ЛПР / DTC-физлицо) — определяет §5.
4. Осведомлённость рынка по Schwartz: Unaware / Problem Aware / Solution Aware / Most Aware.
5. Жёсткие ограничения: бренд-цвета, шрифты, стек (Tailwind? Next?), локали.

## 4. Конверсионная архитектура (холодный трафик, «продать ручку»)

**Осведомлённость (Schwartz):** для Unaware/Problem Aware заголовок бьёт в **симптом проблемы, о которой клиент думает перед сном**, не в продукт. «Купите титановую ручку» — отказ 98%; «Стержень, который не потечёт в самолёте на 10 000 м и не испортит закрытие раунда» — вход в диалог.

**Анатомия первого экрана (холодные продажи):**

- **Eyebrow:** точная идентификация ЦА («Для юристов и инвесторов, подписывающих сделки от $1M+»).
- **H1:** трансформация/нейтрализация катастрофы (конкретная, не «инновационное решение»).
- **Субтитл:** Unique Mechanism без воды («Картридж с избыточным давлением азота. Пишет по маслу и на −30°C»).
- **Primary CTA:** одно контрастное конечное действие; цена и условия видны без скрытых платежей.
- Один оффер → одна аудитория → одно действие. Лендинг — не хоумпейдж.

**Обязательные блоки (порядок = порядок скролла):**

1. **COI-калькулятор (Cost of Inaction):** Loss Aversion λ≈2.25 (Kahneman & Tversky 1979, DOI: 10.2307/1914185) — покажи, сколько денег/нервов горит прямо сейчас, пока юзер скроллит. Формула: (потери/день от старого процесса) × (время саботажа) ≫ цена решения.
2. **Pre-emptive Objection Matrix** — нейтрализуй молчаливый скепсис в порядке появления: «Почему это не развод?» → Level-1 пруфы (видео без склеек, патенты, реестры, сырые логи — не «Иван, Москва»); «Почему вы, а не аналог за 100р?» → физика Unique Mechanism; «А если не подойдёт?» → Risk Reversal.
3. **Exploded View:** послойный чертёж, макросъёмка узлов, стресс-тесты (переезд машиной, заморозка, падение) — инженерные доказательства продают лучше прилагательных.
4. **Us vs Them:** таблица жёсткого контраста по конкретным уязвимостям конкурентов (не абстрактные плюсы/минусы).
5. **Экстремальный Risk Reversal (Skin in the Game):** не «возврат 14 дней», а асимметрия риска в пользу покупателя («протечёт за 365 дней — возврат 100% + 2000₽ за ваши хлопоты»). Без шкуры на кону холодный покупатель дисконтирует обещания до нуля.

**Сканирование:** F/Z-паттерн — глаз цепляет только информационные якоря (числа, контрастные списки, bold-выжимки, подписи к изображениям); абзацы > 2 строк не читаются; Banner Blindness мгновенно выжигает «рекламоподобные» блоки (Status Quo Bias — по умолчанию человек ничего не делает; Samuelson & Zeckhauser 1988, DOI: 10.1007/BF00055564).

## 5. B2B/SaaS vs Consumer/DTC

- **B2B продаёт Information Density, не воздух:** схемы интеграций, структура таблиц, выжимки интерфейса, кейсы, ROI, время внедрения — а не три слова посреди экрана.
- **Contrast Framing:** ЛПР за 0.5 c должен выхватить **Безопасность (SOC2/ISO), SLA (99.99%), время внедрения, калькулятор экономии** — контрастом, а не очередным серым текстом.
- Шейдеры/3D для B2B — 2/10 по ценности; конверсию делает доказательство результата. Consumer/DTC — эмоция и визуал уместнее, но CWV-бюджеты (§8) неизменны.

## 6. Visual Feedback Loop — обязательный контур (G6-гейт для вёрстки)

> Правило дома: **«no render check = no done»** — зеркало FR-004 спеки 004 и Constitution XIII.3. Верстка «вслепую» не сдаётся никогда.

```
Референс + токены ──► Actor (кодер, в рамках дизайн-системы)
        │
        ▼
Dev-сервер ──► Playwright headless (CDP)
        ├── Эшелон 0 (детерминированные линтеры ДО vision-токенов):
        │     • overflow: document.documentElement.scrollWidth > window.innerWidth
        │     • axe-core: WCAG 2.1 AA (контраст, лейблы, клик-зоны ≥24×24px) → JSON за ~40мс
        ├── Эшелон 1 (гигиена headless-рендера):
        │     • await document.fonts.ready ДО скриншота (иначе FOUT → модель «чинит» не сломанное)
        │     • page.emulateMedia({ reducedMotion: 'reduce' }) (иначе снимок transition на opacity 0.3)
        │     • честный DPR: 375px @ deviceScaleFactor 3 и 1440px @ 2
        ├── Эшелон 2 (Dual-Channel Grounding):
        │     • Pixel: скриншоты брейкпоинтов (гештальт, иерархия, ритм)
        │     • Structural: Accessibility Tree (@playwright/mcp) + getBoundingClientRect() подозрительных
        │       элементов («H1 пересекает .hero на 12px по Y» — фактура, не фантазия)
        ▼
Critic (изолированный субагент-«токсичный арт-директор», нулевая память о коде)
        ├── вход: скриншоты + JSON линтеров + a11y tree + design-tokens.json
        ├── выход: дельта-репорт с ТОЧНЫМИ селекторами и правками
        ▼
Actor вносит дельту ──► повтор цикла
        └── Предохранитель сходимости: k ≤ 3 итераций → не сошлось = СТОП-КРАН, вызов человека
```

Правила контура:

- **Actor-Critic разделение обязательно** (Agreeableness Bias: «сам написал — сам похвалил»). Пишет код один агент/сессия, оценивает — другой, без доступа к истории правок.
- **Линтеры раньше Vision-токенов:** не тратить 1500 токенов на контраст, который axe-core считает формулой за 15 мс. Зрение — только на то, что не формализуется (иерархия, ритм, считываемость).
- **Осцилляция (Design Thrashing):** правки только по дельта-репорту Critic с селекторами; «на глаз больше/меньше» запрещено. На k=4 окно контекста уже забито скриншотами и модель теряет логику.
- Дизайн-ревью существующего проекта: тот же Critic-набор поверх текущего рендера (диагностика de-slop: типографика-иерархия, состояния, радиусы, единый набор действий).

## 7. Motion-дисциплина

- Анимация = **доказательство работы механизма** (exploded view, «разборка автомата», стресс-тесты, живой интерфейс в действии), не «вау»-обёртка. Копирование красивых анимаций как путь к конверсии — mostly refuted.
- Целевая дисциплина design-to-motion: **точный кадр → empty state → плавная загрузка → каждый визуал проигрывает свою историю → бесшовный повтор**; фон исходника священен; ничего не кодируется до прохождения статических проверок.
- Порог осознанности: GSAP/Framer Motion — умеренно; Three.js/WebGL — только когда это суть продукта, с бюджетом (§8) и проверкой на 375px @3x.

## 8. Техгигиена выдачи

- Бюджеты: **LCP < 1.2 c, CLS = 0, INP ≤ 200 мс** на мобильной сети; никаких автовоспроизводящихся тяжёлых видео на мобиле; рост LCP 1.5→3 c обваливает конверсию на 16–30% ещё до чтения оффера.
- Server-Side Tracking (GTM Server-Side / CAPI) — иначе блокировщики и iOS Private Relay съедят половину аналитики.
- Проверка по Lighthouse в Эшелоне 0 контура; результаты — артефакт, не впечатление.

## 9. Чек-лист приёмки (негативные проверки — «побег» должен быть невозможен)

1. Ни одного slop-маркера из §1 (проверка глазами Critic + списком).
2. Горизонтальный overflow = 0 на 375px; контраст ≥ 4.5:1 (axe-core: 0 violations).
3. Скриншоты сняты после `fonts.ready` и `reducedMotion`; мобильный — с DPR 3.
4. Все состояния компонентов существуют (hover/focus-visible/active/disabled/loading/error/empty).
5. CWV в бюджете; токены сверены с design-tokens.json.
6. Обжект-матрица и Risk Reversal присутствуют (для продающего лендинга); первый экран по анатомии §4.
7. Critic-дельта пуста ИЛИ k≤3 исчерпано с явным эскалэйтом человеку — «сделал как смог» не сдаётся.
