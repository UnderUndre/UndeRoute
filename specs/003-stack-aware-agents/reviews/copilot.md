## Summary

Сильная сторона: zero-eval сканер, realpath/symlink, детерминизм строки, отказ от lockfile-списков и явные exit-коды проработаны хорошо. Главная слабость: после Q5 транспорт переехал из слота в строку frontmatter, но жизненный цикл этой строки не связан с реальным `sync`. Голый `helpers sync` перезаписывает каждый managed-файл из апстрима и вернёт строку назад (F3). `baseSkills` в виде TS-константы расходится с текущими `skills:` всех четырёх агентов, поэтому на апгрейде `status --strict` станет красным у каждого консьюмера, а `--update-stack` вырежет кураторские скиллы (F4). К этому добавляются процессные дыры: артефакты не в git, Constitution Check сделан по устаревшей v1.5.0, а в действующей v1.7.0 есть VII-B, X и XI. Код-таргет при этом — неотслеживаемый снапшот (F1, F2, F5). До `/speckit.implement` нужен редизайн хранения стековой привязки и повторный analyze.

## Alternative approaches considered

1. **A1 — матрица как данные шаблона.** Каждый `SKILL.md` объявляет свои триггеры во frontmatter (например, `stack: { packages: [next], roles: [frontend] }`), либо рядом с каталогом лежит `.claude/stack-matrix.json`. Матрица версионируется вместе со скиллами, мейнтейнер шаблона правит её без релиза CLI, а CLI только вычисляет. Это закрывает F4 (Principle I), F7 (одно нормативное место) и F17 (skew). `missing_skill_catalog` становится невозможным по построению: нет скилла — нет правила.
2. **A2 — overlay в lock вместо переписывания канона.** База — апстримная строка; стек — дельта `{ add, remove }` по роли, сохранённая в lock. Любой `sync` переприменяет дельту, а `--update-stack` её пересчитывает. `sourceCanonicalHash` остаётся честным, `diff` может показывать дельту отдельно. Закрывает F3.
3. **A3 — `git ls-files` вместо собственного walker.** Детерминированно, совпадает с видом CI, автоматически исключает ворктри, venv и gitignored-мусор. Закрывает F12.
4. **A4 — `confbox` для TOML и YAML.** Уже установлен транзитивно через `c12`; убирает самописный TOML-сканер и даёт YAML-валидацию frontmatter. Закрывает F11 и F16.
5. **A5 — отдельная команда `helpers stack check|apply`** вместо перегрузки `sync` и `status`. Не нужен fetch (NFR-004), не ломается JSON-контракт `status`, rollout становится opt-in; `status --strict` подключает стек, только если в lock есть привязка. Закрывает F14 и F19.
6. **Sidecar из zcode (alt #1)** с учётом нативного preload в CC (F15) не даст эффекта без записи во frontmatter, поэтому A2 предпочтительнее.
