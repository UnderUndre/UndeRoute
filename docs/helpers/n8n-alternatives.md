### ⚖️ 1. Вся правда про лицензию n8n (Sustainable Use License)

Многие думают, что n8n — это Open Source. **Хуй там плавал.** С 2022 года n8n перешел на проприетарную лицензию **Sustainable Use License (SUL)**.

- **Что РАЗРЕШЕНО (бесплатно):**
  1. Юзать внутри своей конторы для внутренних нужд.
  2. Поднимать клиенту **отдельный его личный инстанс** на его сервере (Hetzner / VPS) в рамках разовой настройки/консалтинга.
- **Где начинается ПОЛНЫЙ ПИЗДЕЦ (Нарушение лицензии):**
  1. **Мультитенант хостинг:** Ты НЕ имеешь права поднять один мощный сервер с n8n и крутить на нем воркфлоу для 10 разных клиентов за абонентскую плату, если ценность услуги — сам n8n.
  2. **Встраивание в SaaS (White-label / Embed):** Если ты делаешь SaaS и хочешь встроить внутрь движок n8n, чтобы пользователи твоей платформы неявно гоняли через него данные — тебе нужен **Embed License**, который стоит **от $50,000 в год** (пятьдесят тысяч баксов, Карл!).
  3. **Перепродажа доступа к UI:** Брать с клиентов деньги за логин в инстанс n8n строго запрещено.

> **Итог по лицензии:** Если ты делаешь разовую настройку на сервере заказчика — SUL прокатит. Но если строишь масштабируемый SaaS или единый хаб для клиентов — ты ходишь по минному полю, где наступишь на иск от юристов n8n GmbH.

### 🤮 2. Почему визуальный n8n для нормального кодера — это гофра вместо трубы

Давай честно: n8n придумали для маркетологов, продактов и no-code интеграторов, которые не умеют писать циклы и ловить промисы.

Когда ты, будучи программистом, лезешь в n8n, ты получаешь:

1. **Проблемы с Git и версионированием:** Воркфлоу хранятся в гигантских JSON-простынях на 5000 строк. Попробуй разрулить merge conflict в JSON-файле n8n при командной разработке — проклянешь всё на свете.
2. **Нет нормальных тестов:** Ты не можешь натравить `vitest` или `jest` на цепочку нод, замокать API и прогнать CI/CD пайплайн перед деплоем.
3. **Ад с типами:** Внутри нод данные летают как нетипизированный `any`, и чтобы не словить ошибку в рантайме, приходится городить костыли с Zod.
4. **Костыльный ИИ-вайбкодинг:** MCP-сервер к n8n — это буквально попытка научить Claude через костыли кликать по визуальным нодам, хотя LLM **в 100 раз лучше пишет чистый TypeScript-код** в твоем любимом Cursor / Windsurf.

#### 🔥 Вариант №1: Trigger.dev v3 (Главный убийца n8n для разработчиков)

Это фреймворк фоновых задач с **durable execution** (живучим выполнением). Лицензия — **чистый Apache 2.0** (можно хостить самому, встраивать в любой SaaS, продавать клиентам, никаких $50k лицензий).

- **Как пишется код (чистый TS + Zod):**

```typescript
import { task, wait } from "@trigger.dev/sdk/v3";
import { z } from "zod";

export const processLeadWorkflow = task({
  id: "process-lead",
  run: async (payload: { email: string; companyUrl: string }) => {
    // 1. Спарсить данные компании
    const companyData = await scrapeCompany(payload.companyUrl);

    // 2. Сгенерировать оффер через Claude 3.7
    const aiPitch = await generatePitch(companyData);

    // 3. Пауза на 2 часа (сервер не висит, память не жрется!)
    await wait.for({ hours: 2 });

    // 4. Отправить письмо через Resend
    return await sendEmail({ to: payload.email, body: aiPitch });
  },
});
```

- **Плюсы:** Работает без таймаутов (хоть на 5 часов запускай парсинг), автоматические ретраи упавших шагов, идеальный дашборд со всеми логами из коробки.

#### 🔥 Вариант №2: Inngest (Zero-Infra внутри Next.js)

Если ты собираешь 14-дневный SaaS на `nextjs/saas-starter` — тебе даже отдельный контейнер под воркер поднимать не надо!

- Inngest живет прямо в папке `app/api/inngest/route.ts`.
- Вся оркестрация шагов (`step.run`, `step.sleep`, `step.ai`) пишется обычными функциями прямо в репозитории проекта.
- Полная типизация, мгновенный деплой на Vercel.
